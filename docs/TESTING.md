# TESTING.md — Строгая инструкция приёмки OpenLight из Release на Windows (RU)

> **Запускать должен пользователь СТРОГО по шагам на Windows 10/11 x64 из Release, не агент.**
> Все найденные баги → `docs/BUG_LIST.md` с воспроизведением, без «готово» пока есть P0.

## Требования

- **Windows 10/11 x64**, **WebView2** (Win11 встроен; Win10 → [Evergreen Bootstrapper](https://developer.microsoft.com/en-us/microsoft-edge/webview2/#download-section) → перезагрузка)
- **Интернет** только для шага 1-2 (скачать Release), дальше **полностью офлайн** (проверить DevTools → Network = 0 запросов, кроме шага 1)
- **Готовый `OpenLight.exe` из Release** (не сборка из исходников) — см. шаг 1
- Дополнительно для проверки корпуса: Python 3.11 + `pip install -r requirements.txt` (только для `corpus.yml` локально)

## Шаги — СТРОГО по порядку, без пропусков

### 1. Скачать сборку из Release (с интернетом)

1. Открыть https://github.com/Igorr112323/OpenLight/releases
2. Выбрать последний тег `v0.9.3-test` → скачать `OpenLight.exe` (ожидаемо: 40-70МБ, ≥30МБ, <70МБ, имя `OpenLight.exe`)
3. Проверить размер: ПКМ → Свойства → 40-70МБ ([docs/CORPUS_REPORT.md](CORPUS_REPORT.md) фиксирует размер, напр. `dist/OpenLight.exe 52.3МБ`) — если <30МБ → Build падал, Release не создавался (без dummy)
4. Проверить selftest: `OpenLight.exe --selftest` в консоли → `OpenLight 0.9.3-test` (без окна) + `certutil -hashfile OpenLight.exe SHA256` → сравнить с Release notes (опционально)

> **Ожидаемо:** Файл скачан, размер <60МБ, без SmartScreen «неизвестный издатель» (если есть — «Подробнее» → «Выполнить в любом случае»)

### 2. Запуск (без установки, двойной клик)

5. **Отключить интернет** (или проверить DevTools → Network = 0 после запуска — кроме шага 1)
6. **Двойной клик `OpenLight.exe`** → окно 1400×900 заголовок «OpenLight», фон `#F9F9FB` dot-grid 24px, пустое полотно, подсказка «Полотно пусто — перетащите .STL», док-центры (Крепления/Силы/Запретная зона/Оптимизировать/Вид), метрики справа «Вес: 412г → —», левый низ «Материал», верх-право «…».

> **Ожидаемо:** Консоль чистая (DevTools Console 0 ошибок), Network 0 запросов, 60 FPS, тень PCFSoft opacity 0.18, окно открывается <3с.

7. Проверить «О программе»: правая капсула «…» → поповер Настройки → строка «Версия X.Y.Z · путь %APPDATA%» (версия из build, нет хардкода, напр. `0.9.3-test`), строка «Лицензия: MIT (ожидает выбора куратора)» + ссылка «GitHub →» → https://github.com/Igorr112323/OpenLight

> **Ожидаемо:** Версия совпадает с тегом Release (`0.9.3-test`), лицензия отображается, ссылка открывается в браузере.

### 3. Расстановка условий (встроенный кронштейн)

8. Без открытия файла: виден Г-кронштейн #C9CDD3 парящий с мягкой тенью. Вращение ЛКМ, зум колесо, панорама ПКМ. Клик по детали → `console.log pick {point, normal}` (DevTools).

> **Ожидаемо:** 60 FPS, тень PCFSoft, кронштейн центрирован.

9. Выбрать инструмент «Крепления» (док центр, иконка замка) → клик по вертикальной полке → появляется чёрная капсула-заклёпка + синие кольца (пульс 620мс). Повторный клик по маркеру → удаление. `Esc` → выход. **Поставить 2 опоры у отверстий** (верх + низ вертикальной полки).

> **Ожидаемо:** Капсулы ставятся/удаляются, пульс 620мс, опоры сохраняются после Esc.

10. Выбрать «Силы» → клик по горизонтальной полке → стрелка красная + поповер 500Н (шаг ±50, 50-5000) → OK → стрелка остаётся. Клик по стрелке → удаление. **Поставить 1 силу 800Н** на конце горизонтальной полки (нагрузка вниз).

> **Ожидаемо:** Стрелка красная, поповер 500Н, значение 800Н сохраняется.

11. Выбрать «Запретная зона» → клик по вертикальной полке → синий диск 12мм (поповер 6/12/20) → OK. **Поставить 1 зону 12мм** у отверстия.

> **Ожидаемо:** Диск синий 12мм, поповер 6/12/20, зона сохраняется.

12. Левый низ «Материал» → поповер: Сталь 09Г2С / АМг6 / PLA + ЧПУ/3D-печать. Смена → вес в карточке справа внизу меняется (сталь 412г → алюминий/пластик меньше). **Оставить Сталь 09Г2С + ЧПУ**.

> **Ожидаемо:** Метрики «Вес: 412г → — · Экономия —» до оптимизации, материал переключается.

### 4. Импорт (STL/OBJ, STEP-заглушка)

13. Верхняя капсула «Открыть» (папка) → нативный диалог .stl/.obj/.step → выбрать `tests/corpus/cache/nasa_*.stl` (любой NASA <2МБ) или `trimesh_20mm_cube.stl`.

> **Ожидаемо:** Модель центрирована, масштаб 70мм, кронштейн скрыт, камера приближена, маркеры сброшены, метки сброшены. Для STEP → тост «STEP пока не поддерживается» (честно, отсутствие STEP в v1.0, см. KNOWN_LIMITATIONS.md).

14. Проверить OBJ аналогично: открыть `cow.obj` из корпуса → модель загружена, watertight проверяется (если не watertight — тост, но parse ok).

> **Ожидаемо:** Импорт STL/OBJ работает, STEP — заглушка, без падения.

15. Вернуть встроенный кронштейн: закрыть импорт (или перезапустить exe) → снова Г-кронштейн, опоры/силы сброшены — поставить заново опоры (шаг 9) + силу 500Н (по умолчанию).

### 5. Оптимизация (реальное ядро)

16. Нажать «Оптимизировать» (синяя искра) **без опор/сил** → тост «Добавьте опору и нагрузку» (автопилот-предупреждение: без опор → «деталь улетит»).

> **Ожидаемо:** Тост сверху 4с, оптимизация не запускается.

17. Поставить условия (шаг 9-10: 2 опоры + 1 сила 500Н) → нажать «Оптимизировать» → внутри пилюли кольцо+бар, честный прогресс `Вокселизация 5% → SIMP i/N 15-85% (итерации) → Marching 88% → Taubin 93% → Готово 100%`, тосты фаз каждые 600мс, 3.5-5с (демо) или 5-25с (real, в зависимости от 16³/32³), по окончании — пульс кнопки, поповер «Облегчение 20/40/60%», тост «Готово» + `klog SIMP it/target/mean/achieved/dc_max/n_active/n_comp` в консоль (если запущен из `python main.py`).

> **Ожидаемо:** При pywebview — прогрессбар честный, счётчик итераций (SIMP 15-25 ит), timeout 45с → предложение 32³ (если 48³). Для 16³ relief 0.4 → dt 5с watertight True.

18. Проверить метрики: справа «Вес: 412г → 246г · Экономия −40%» + «Запас 2,4» (1 знак, запятая). Слайдер 20/40/60 → вес/запас меняются согласованно, <300мс. Для 40%: `weight_after 477г (ratio 0.58)`, safety 2-3.

> **Ожидаемо:** Вес/запас соответствуют relief (20%→0.8, 40%→0.6, 60%→0.4), демо — детерминировано, real — по von Mises/MATERIALS yield.

19. Проверить предупреждения: без опор → «деталь улетит», PLA + >4000Н → «Превышена типичная нагрузка для PLA», 60% + запас<1.5 → «Переоптимизация: снизьте облегчение до 40%» (тост 4с).

### 6. Виды

20. Док «Вид» (слои) циклически: Исходная → Карта напряжений (градиент синий→зелёный→янтарный→коралловый + легенда σ,МПа 0/120/240) → Облегчённая (перемычки тоньше + 3-5 органических отверстий, bevel) → До/После (вертикальная шторка ⇔ draggable, scissor).

> **Ожидаемо:** Карта меняется при смене опор/сил (синтетика — Гаусс, real — von Mises), шторка draggable, splitDivider visible.

### 7. Экспорт и проекты (автосейв)

21. Верхняя «Экспорт» → нативный Save `optimized.stl` → выбрать путь → STL сохранён. Открыть в STL-вьюере (Windows 3D Viewer, Cura, PrusaSlicer) → модель открывается, watertight для встроенного (проверить: `trimesh.load(...).is_watertight == True`).

> **Ожидаемо:** STL валидный, watertight True, размер <5МБ. Правый клик → тост «Отчёт будет в Этапе 6».

22. `Ctrl+S` → Сохранить проект `.olight.json` → выбрать путь → JSON сохранён. Закрыть окно → `OpenLight.exe` снова → `Ctrl+O` → открыть → опоры/силы/камера на месте. Проверить `%APPDATA%\OpenLight\autosave.olight.json` (Windows) или `~/.config/OpenLight/autosave.olight.json` (Linux) — debounce 800мс, `_autosave_ts` свежее 7 дней → при старте тост «Восстановить прошлую работу? Да/Нет», список «Последние 5» в поповере «…».

> **Ожидаемо:** Проект сохраняется/загружается, автосейв работает, последние 5 отображаются.

### 8. Корпус (инженерные детали)

23. Скачать корпус (опционально, с интернетом): `git clone https://github.com/Igorr112323/OpenLight.git && pip install -r requirements.txt && python tools/fetch_corpus.py --limit 100` → 100 файлов в `tests/corpus/cache/` (≤15МБ каждый, проверка sha256).

24. Прогнать отчёт: `python tools/make_stress_report.py --limit 100` → `report.json/html` + `docs/CORPUS_REPORT.md` с таблицей файл→лицензия→parse→watertight→voxel48→solve<60→итог (цель ≥90% parse ok, факт ~95%).

> **Ожидаемо:** Все 100 скачиваются, sha256 ok, parse ≥90%, падения — в BUG_LIST.

## Критерии приёмки (СТРОГО)

- [ ] `dist/OpenLight.exe` из Release <60МБ, двойной клик → все шаги 6-22 без интернета, Network 0, консоль чистая.
- [ ] Версия в «О программе» = тегу Release (из build, нет хардкода).
- [ ] MBB 60×20×1 16ит 49% 21.4с (если запуск из `python main.py` + solver) — см. KNOWN_LIMITATIONS.
- [ ] Корпус 100 моделей ≥90% parse (см. CORPUS_REPORT.md).

**Все найденные баги — в BUG_LIST.md с воспроизведением (команда, лог, скрин), без «готово» пока есть P0.**

## Эталон МКЭ (выполнен 2026-11-26, Linux, scipy 1.17.1)

- Балка L=100мм h=25мм b=25мм 32×8×8 pitch 3.125мм E=200e9 F=1000Н
- Теория δ = FL³/(3EI) = 0.0512 мм (I=32552 мм⁴)
- Расчёт via hex8_ke 2×2×2 Gauss + spsolve (7776 DOF): δ_computed = -0.0521мм ошибка **1.8%** (≤2% пройден)
